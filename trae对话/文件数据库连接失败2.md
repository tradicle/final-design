### 4.2 系统逻辑架构设计

为了保证系统具有较好的可维护性和扩展性，本课题采用前后端分离的 B/S 架构模式，并结合 Spring Boot、Vue3、MyBatis-Plus 和 MySQL 等技术完成平台搭建。系统逻辑架构如图4-2所示。

图4-2 系统逻辑架构图

从逻辑层次上看，系统主要由用户层、表现层、业务层、数据访问层和数据存储层五个部分组成。

（1）用户层  
用户层主要包括普通用户和管理员两类角色。普通用户通过浏览器访问平台首页、领养中心、资讯页面、社区页面和捐助认领页面等前台模块；管理员在登录后进入后台管理平台，完成数据维护、业务审核和统计查看等操作。用户层是系统服务对象的直接体现，其角色划分决定了系统的权限边界和交互方式。

（2）表现层  
表现层主要由前端页面和交互逻辑组成，采用 Vue3、TypeScript、Vite 和 Element Plus 实现。该层负责页面渲染、状态展示、表单输入、用户操作反馈和路由跳转等工作。表现层通过 Axios 调用后端提供的 RESTful API 接口，实现与业务层的数据交互。

（3）业务层  
业务层是系统的核心处理层，由 Spring Boot 提供支撑。该层主要负责用户登录校验、宠物档案管理、领养申请处理、社区帖子与评论管理、物资认领审核、资讯发布和统计数据汇总等业务逻辑。业务层通过控制器、服务层和相关配置类协同工作，是系统实现具体功能的关键部分。

（4）数据访问层

（5）数据存储层  
数据存储层主要采用 MySQL 实现业务数据持久化，用于存储用户信息、宠物档案、领养申请、帖子评论、资讯内容、物资认领、公示记录等核心业务数据。同时，系统中的图片资源通过本地文件目录进行保存，并通过静态资源映射提供访问路径。数据存储层为系统运行提供了稳定的数据支撑。

通过上述逻辑架构设计，系统实现了界面展示、业务处理和数据存储的分层管理。该设计一方面提高了系统结构的清晰度，另一方面也便于后续对各层模块进行独立维护和功能扩展。

### 4.3 系统业务流程设计

校园流浪动物救助与云领养管理平台涉及用户浏览、申请提交、后台审核和内容公示等多个环节。为了进一步明确系统各功能模块之间的交互关系，需要对系统的核心业务流程进行说明。整体来看，本系统主要围绕领养流程、物资认领流程、社区互动流程和后台运营流程展开。

（1）领养业务流程  
普通用户首先在平台中浏览宠物档案列表，查看宠物详情、图文介绍和活动范围等信息；在确认领养意向后，用户需先阅读领养须知，再登录系统并填写领养申请表单；申请提交后，后台管理员对申请信息进行查看、审核和备注处理；审核通过后，系统完成从“浏览—申请—审核”的基本业务闭环。

（2）物资认领业务流程  
用户进入捐助页面后可查看当前平台急需物资清单、相关联系人和公示记录；在有意向支持的情况下，用户登录系统并填写物资认领信息；管理员在后台审核认领申请，并根据审核结果进行通过或拒绝处理，同时记录审核说明；最终形成“需求发布—用户响应—后台审核”的业务链路。

（3）社区互动业务流程  
普通用户登录后，可以在社区模块发布帖子、上传图片并记录位置信息；其他用户可以对帖子进行评论和回复；管理员则负责在后台对不合规内容进行审核与处理。该流程体现了用户之间以及用户与管理员之间的双向互动关系。

（4）后台运营业务流程  
管理员登录后台后，可以查看仪表盘统计信息，并根据平台运营需要进入宠物管理、资讯管理、申请审核、社区审核和物资认领审核等页面执行相应操作。后台运营流程贯穿系统日常维护全过程，是保障平台持续稳定运行的重要部分。

### 4.4 系统接口与权限概要设计

在前后端分离架构下，系统各模块之间的业务联动主要依赖统一的接口设计来实现。为了提高接口可读性和后续维护效率，本系统总体采用 RESTful 风格进行接口组织。系统按照资源类型划分接口路径，例如用户相关接口、宠物档案接口、领养申请接口、社区接口、物资认领接口和后台管理接口等，尽可能保证命名统一、语义清晰和职责明确。

在权限控制方面，系统采用“前端路由守卫 + 后端会话拦截”的双重校验模式。前端通过路由元信息判断用户是否已登录、是否具有管理员权限，并对页面访问进行控制；后端在用户登录成功后通过 Session 保存登录信息，并在关键接口处统一进行会话校验和角色判定。对于宠物档案维护、后台审核、文件上传、发帖评论和认领申请等关键操作，系统都会进行登录校验；对于后台接口和管理操作，则进一步要求用户必须具备管理员权限。

这种接口与权限设计方案具有以下优点：一是能够增强系统访问控制能力，避免仅依赖前端页面隐藏造成的伪权限问题；二是能够保证各业务模块之间的接口组织更加规范，便于后期功能扩展与联调测试；三是有利于在论文中体现系统设计的完整性和工程化程度。

### 4.5 数据库概要设计

数据库是系统运行的重要支撑。校园流浪动物救助与云领养管理平台在运行过程中需要对用户信息、宠物档案、领养申请、社区互动内容、物资认领记录和透明公示数据等进行统一存储与管理，因此数据库设计必须能够满足数据结构清晰、业务关系明确和后续扩展方便等要求。

结合本系统业务内容，数据库主要围绕以下几类核心实体进行设计：系统用户、宠物档案、宠物位置记录、领养申请、资讯内容、社区帖子、社区评论、物资认领、急需物资、捐助记录、透明公示和系统配置等。上述实体之间存在较为明确的关联关系，例如用户可以提交领养申请、发布社区帖子和评论；宠物档案可以关联多个位置记录，也可以对应多条领养申请记录；帖子与评论之间具有主从关系等。

在数据库选型方面，系统采用 MySQL 作为关系型数据库管理系统。MySQL 具有部署方便、性能稳定、生态成熟和学习成本较低等优点，能够满足本科毕业设计规模下的系统开发和运行需求。数据库表结构设计不仅要满足当前业务使用，还应保留一定扩展空间，以便后续增加更多角色、消息通知、举报机制或推荐功能。

从概要设计角度看，系统数据库结构可分为以下两类：

（1）基础数据类  
主要包括用户表、系统配置表等，用于支撑平台身份识别、权限区分和基础配置维护。

（2）业务数据类  
主要包括宠物档案表、宠物位置表、领养申请表、资讯表、帖子表、评论表、物资认领表、急需物资表、捐助记录表、透明公示表等，用于支撑平台核心业务流程。

通过数据库概要设计，系统基本明确了数据实体组成及其关系，为后续数据库详细设计和数据表字段设计提供了依据。
